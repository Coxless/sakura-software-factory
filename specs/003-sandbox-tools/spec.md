## Clarifications

### Session 2026-11-10

- Q: エージェントが作業ディレクトリの `.git`（フックや設定）を書き換えられると、ホストが commit したときにホストでコードが動いてしまう。どう防ぐか？ → A: `.git` はコンテナに読み取り専用で見せる。ガードでも `.git` への書き込みを拒否する。コンテナ内で `git diff` などの読み取りはできるが、commit はできない（commit はホストだけが行う。原則 IV）
- Q: 作業ディレクトリ内のシンボリックリンクを通して、作業ディレクトリの外や禁止パスに書き込まれるのをどう防ぐか？ → A: 読み書きのツールは、パスをコンテナ内で実際のパスに解決してから、解決後のパスでも作業ディレクトリ内・禁止パス外かを確かめる。名前だけでの確認では通さない
- Q: `bash` で禁止パス（`.github/workflows` など）を書き換えることは防げるか？ → A: 完全には防がない。`bash` のガードは危険なコマンドの形を拒否する「やわらかい層」とし、禁止パスの変更は 008 の出荷前チェック（層6）が diff で必ず検出する。本当の防御はコンテナの隔離（ネットワークなし・読み取り専用ルート・`.git` 読み取り専用）で行う

## User Scenarios & Testing *(mandatory)*

この機能の利用者は2種類いる。

- **実装役のエージェント**（004 で作る）: ツールを呼んで対象リポジトリを読み書きし、コマンドを実行する
- **ファクトリーの開発者・運用者**: ジョブごとの作業場を用意・破棄し、ツール呼び出しがどこまで許されるかを決める

### User Story 1 - 隔離された作業場をジョブごとに用意し、片付ける (Priority: P1)

ファクトリーは、ジョブごとに専用の隔離された作業場（コンテナ）を用意し、clone 済みの作業ディレクトリをそこに見せる。作業場はネットワークに出られず、作業ディレクトリと一時領域以外には書き込めず、特権を持たず、CPU・メモリ・プロセス数が制限される。ジョブが終わる（成功・失敗・例外のどれでも）と作業場は必ず片付けられる。

**Why this priority**: 原則 IV（NON-NEGOTIABLE）の「本当の防御」そのもの。これがないと 4ツールも実装役も動かせない。

**Independent Test**: 作業場を用意し、中から外部への通信・作業ディレクトリ外への書き込み・権限の昇格・制限を超えるプロセス生成がすべて失敗すること、作業ディレクトリへの書き込みはホストから見えること、片付けたあと作業場が残っていないことを確かめる。

**Acceptance Scenarios**:

1. **Given** clone 済みの作業ディレクトリ、**When** 作業場を用意する、**Then** 作業場の中から作業ディレクトリを読み書きでき、書いた内容がホストの作業ディレクトリに反映される
2. **Given** 用意した作業場、**When** 中から外部のホストに接続しようとする、**Then** 失敗する
3. **Given** 用意した作業場、**When** 作業ディレクトリと一時領域以外（システムの領域）に書き込もうとする、**Then** 失敗する
4. **Given** 用意した作業場、**When** 中で実行しているユーザーと権限を調べる、**Then** 管理者ではなく、特権を1つも持たない
5. **Given** 用意した作業場、**When** 作業ディレクトリの `.git` の中に書き込もうとする、**Then** 失敗する
6. **Given** 用意した作業場、**When** ジョブの処理が例外で終わる、**Then** 作業場は片付けられ、残らない
7. **Given** 前回の異常終了で残った作業場、**When** ファクトリーが起動する、**Then** ファクトリーが作った作業場の残りを片付ける

---

### User Story 2 - 4つのツールで作業ディレクトリを操作する (Priority: P1)

実装役は、ファイルの読み取り・書き込み・部分置換と、シェルコマンドの実行の4つのツールで作業する。ツールはすべて作業場の中で実行され、結果（内容・終了コード・出力）が実装役に返る。誤った使い方（存在しないファイル、置換元が見つからない・複数ある、時間切れ）は、実装役が次の手を決められる説明付きのエラーとして返る。

**Why this priority**: 実装役（004）の手足。ツールの返すメッセージの質が実装役の成功率を左右する（`04` 1章）。

**Independent Test**: 作業場に対して4ツールを直接呼び、正常系と誤用時の結果を確かめる。LLM は使わない。

**Acceptance Scenarios**:

1. **Given** 作業ディレクトリのファイル、**When** 読み取りツールを呼ぶ、**Then** 行番号付きの内容が返る。開始行と行数を指定すればその範囲だけが返る
2. **Given** 存在しないパス、**When** 読み取りツールを呼ぶ、**Then** 「ファイルがない」ことを示すエラーが返る
3. **Given** 存在しないディレクトリの下のパス、**When** 書き込みツールを呼ぶ、**Then** 途中のディレクトリが作られてファイルが書かれる
4. **Given** ファイルに1回だけ現れる文字列、**When** 部分置換ツールを呼ぶ、**Then** その1か所だけが置き換わる
5. **Given** ファイルに現れない文字列、または2回以上現れる文字列（全置換の指定なし）、**When** 部分置換ツールを呼ぶ、**Then** ファイルは変わらず、見つからない／何か所あるかを示すエラーが返る
6. **Given** シェルコマンド、**When** 実行ツールを呼ぶ、**Then** 終了コードと標準出力・標準エラーが返る。0 以外の終了コードもエラーではなく結果として返る
7. **Given** 時間の上限を超えるコマンド、**When** 実行ツールを呼ぶ、**Then** 上限で打ち切られ、打ち切ったことが結果に示される

---

### User Story 3 - ツール呼び出しを実行前に検査する（層3） (Priority: P1)

ファクトリーは、ツールの実行前に検査を順に通し、1つでも拒否したら実行せず、理由をツールの結果として実装役に返す。検査は、作業ディレクトリの外へのアクセス、禁止パス（CI の定義・環境変数ファイル・ロックファイル・デプロイ設定・`.git`）への書き込み、危険なコマンドの形を拒否する。検査は部品として足し外しでき、順番に合成される。

**Why this priority**: `04` 2章 層3。サンドボックスの手前で、実装役の誤り・プロンプトインジェクションによる逸脱を早く止め、理由を返して軌道修正させる。

**Independent Test**: 検査の合成関数に、許可されるべき呼び出しと拒否されるべき呼び出しを与え、判定と理由を確かめる。シンボリックリンク経由の書き込みは作業場を使って確かめる。

**Acceptance Scenarios**:

1. **Given** 作業ディレクトリの外を指すパス（絶対パス、`..` を含むパス）、**When** 読み書きツールを呼ぶ、**Then** 実行されず、作業ディレクトリ外であることを示す理由が返る
2. **Given** 禁止パス（例: `.github/workflows/ci.yml`、`.env`、`pnpm-lock.yaml`、`.git/hooks/pre-commit`）、**When** 書き込み・部分置換ツールを呼ぶ、**Then** 実行されず、禁止パスであることを示す理由が返る
3. **Given** 禁止パスを指すシンボリックリンクが作業ディレクトリにある、**When** そのリンクに書き込もうとする、**Then** 実行されず、拒否の理由が返る
4. **Given** 危険なコマンドの形（例: 作業ディレクトリ外の再帰削除、外部からのスクリプトの取得と実行、`git push`、権限の昇格）、**When** 実行ツールを呼ぶ、**Then** 実行されず、拒否した形を示す理由が返る
5. **Given** 複数の検査を合成したもの、**When** 前の検査が拒否する、**Then** 後ろの検査は実行されず、最初に拒否した検査の理由が返る
6. **Given** 禁止パスの一覧、**When** 設定で変える、**Then** 検査がその一覧に従う

---

### User Story 4 - ツールの結果を整えてから返す（層4） (Priority: P2)

ファクトリーは、ツールの結果を実装役に返す前に、長い出力を前後を残して切り詰め、秘密情報らしい文字列を伏せる。整える処理も部品として合成できる。

**Why this priority**: `04` 2章 層4。長いテストログでコンテキストとリクエスト数を浪費しないため、軌跡と LLM に秘密情報を流さないために要る。ただし P1 の3つがあれば実装役は動くので P2 とする。

**Independent Test**: 長い出力・秘密情報を含む出力を与え、整えた結果の長さと内容を確かめる。

**Acceptance Scenarios**:

1. **Given** 上限を超える長さの出力、**When** 結果を整える、**Then** 先頭と末尾が残り、間を省いたことと省いた量が示される
2. **Given** トークンや秘密鍵を含む出力、**When** 結果を整える、**Then** その値は伏せ字に置き換わる
3. **Given** 上限以下で秘密情報を含まない出力、**When** 結果を整える、**Then** 変わらない

---

### User Story 5 - 依存をインストールする一時的な作業場 (Priority: P2)

ファクトリーは、ジョブの準備工程で、依存のインストールだけをネットワークありの一時的な作業場で行い、終わったら片付ける。この作業場にも秘密情報は渡さない。インストールした依存は、そのあとのネットワークなしの作業場から使える。

**Why this priority**: `03` 4章 #2。テストを実行するには依存が要るが、実装工程の作業場はネットワークなしにする必要がある。

**Independent Test**: ロックファイル付きの小さなリポジトリで、一時的な作業場でインストールしたあと、ネットワークなしの作業場でその依存を使うコマンドが通ることを確かめる。

**Acceptance Scenarios**:

1. **Given** ロックファイル付きの作業ディレクトリ、**When** 依存のインストールを実行する、**Then** 作業ディレクトリに依存が入り、一時的な作業場は残らない
2. **Given** インストール済みの作業ディレクトリ、**When** ネットワークなしの作業場でテストコマンドを実行する、**Then** 依存を使って実行できる
3. **Given** 時間の上限を超えるインストール、**When** 実行する、**Then** 打ち切られ、失敗として返り、一時的な作業場は残らない
4. **Given** 一時的な作業場、**When** 中の環境変数を調べる、**Then** ファクトリーの APIキー・トークンは含まれない

---

### Edge Cases

- 作業場の用意に失敗する（イメージがない、コンテナの実行環境が動いていない）→ 原因を示すエラーで失敗し、途中まで作ったものを残さない
- ツールの実行中に作業場が消えた（メモリ超過で落ちたなど）→ ツールは作業場が使えないことを示すエラーを返す
- バイナリファイルや巨大なファイルを読む → バイナリはその旨だけを返し、巨大なファイルは上限で切り詰めて続きの読み方を示す
- 読み書きのパスが空・作業ディレクトリそのもの・ディレクトリ → 説明付きのエラーにする
- 書き込む内容が空 → 空のファイルを書く（エラーにしない）
- 置換元と置換先が同じ → 変更がないことを示すエラーにする
- 改行コードが CRLF のファイルを部分置換する → 元の改行コードを保つ
- コマンドが子プロセスを残したまま終わる・時間切れになる → 上限で打ち切って結果を返す。残ったプロセスは作業場を片付けるときに消える
- 出力に UTF-8 として不正なバイトが含まれる → 置換文字にして返す（例外にしない）
- ツールの引数がスキーマに合わない → 実行せず、どの引数がどう違うかを返す

## Requirements *(mandatory)*

### Functional Requirements

**作業場（層5）**

- **FR-001**: ファクトリーは、作業場用の専用イメージを持たなければならない。イメージには、対象リポジトリ（TypeScript）の作業に要るランタイム・パッケージマネージャー・git・高速な検索ツールを含め、作業場の中からダウンロードせずに使えるようにする
- **FR-002**: 作業場はジョブごとに1つ作り、ジョブを識別できる名前と、ファクトリーが作ったことを示す印を付けなければならない
- **FR-003**: 実装工程の作業場は、次をすべて満たさなければならない: ネットワークなし、ルートファイルシステムは読み取り専用（作業ディレクトリと大きさに上限のある一時領域だけ書き込み可）、特権をすべて外す、権限の昇格を禁止する、管理者でないユーザーで動かす、CPU・メモリ・プロセス数に上限を設ける
- **FR-004**: 作業ディレクトリの `.git` は作業場から読み取り専用でしか見えてはならない
- **FR-005**: 作業場にはファクトリーの環境変数を引き継がず、APIキー・トークン・秘密鍵を渡してはならない。作業場に渡す環境変数は決まった一覧（ホームディレクトリなど）に限る
- **FR-006**: 作業場は、ジョブの成功・失敗・例外のどれでも必ず片付けなければならない。片付けは何度呼んでも失敗しない
- **FR-007**: ファクトリーは起動時に、前回の異常終了で残った自分の作業場を片付けられなければならない
- **FR-008**: 依存のインストールは、ネットワークありの一時的な作業場で、与えられたコマンドを1回だけ実行して片付けなければならない。ネットワーク以外の隔離（FR-003〜FR-005）は実装工程と同じにし、時間に上限を設ける
- **FR-009**: 作業場の資源の上限（CPU・メモリ・プロセス数・一時領域の大きさ）、イメージ名、実行ユーザー、時間の上限は設定で変えられなければならない

**4ツール**

- **FR-010**: ファクトリーは、ファイルの読み取り・書き込み・部分置換・シェルコマンドの実行の4つのツールを、名前・説明・引数のスキーマ付きで提供しなければならない。ツールの実行はすべて作業場の中で行う
- **FR-011**: 読み取りツールは、行番号付きで内容を返し、開始行と行数で範囲を指定できなければならない。返す量には上限を設け、超えたら続きの読み方を示す
- **FR-012**: 書き込みツールは、ファイルを丸ごと書き、途中のディレクトリがなければ作らなければならない
- **FR-013**: 部分置換ツールは、置換元の文字列がちょうど1回現れるときだけ置き換えなければならない（全置換の指定があれば全部）。見つからない・複数ある・置換元と置換先が同じ場合はファイルを変えず、理由を返す
- **FR-014**: 実行ツールは、作業ディレクトリでコマンドを実行し、終了コード・標準出力・標準エラーを返さなければならない。時間の上限（既定値あり。呼び出しごとに上限の範囲で指定できる）を超えたら打ち切り、そのことを結果に示す
- **FR-015**: ツールの失敗（誤用・作業場の異常）は、例外でループを止めずに、エラーであることがわかる結果として返さなければならない
- **FR-016**: ツールの結果は、実装役のエージェント（004）がそのまま使える形（モデルに返す文字列と、記録用の構造化した詳細）で返さなければならない
- **FR-017**: ツールは同時に1つずつ実行される前提で作る（並列実行に対応しなくてよい）

**ツールの検査（層3）と結果の整形（層4）**

- **FR-018**: ファクトリーは、実行前の検査を順に実行し、1つでも拒否したら残りを実行せず、最初の拒否の理由を返す合成関数を提供しなければならない
- **FR-019**: 実行後の整形を順に適用する合成関数を提供しなければならない
- **FR-020**: 読み書きのツールは、作業ディレクトリの外を指すパスを拒否しなければならない。パスは名前の上でと、作業場の中で実際のパスに解決した後との両方で確かめる
- **FR-021**: 書き込み・部分置換のツールは、禁止パスへの書き込みを拒否しなければならない。禁止パスは設定で持ち、既定は CI の定義（`.github/workflows`）・環境変数ファイル（`.env`）・ロックファイル・デプロイ設定・`.git` とする
- **FR-022**: 実行ツールは、危険なコマンドの形を拒否しなければならない。少なくとも、作業ディレクトリ外やルートの再帰削除、外部から取得したスクリプトの実行、リモートへの push、権限の昇格、コンテナの操作、ファイルシステムの作成・マウントを含める
- **FR-023**: 拒否の理由は、実装役が別の手を選べるように、何を・なぜ拒否したかを含めなければならない
- **FR-024**: 結果の整形は、出力の長さが上限を超えたら先頭と末尾を残して切り詰め、省いた量を示さなければならない。上限は設定で変えられる
- **FR-025**: 結果の整形は、秘密情報らしい文字列を伏せ字にしなければならない（001 のログと同じ判定を使う）
- **FR-026**: 検査と整形の関数は、実装役のエージェントのフック（実行前・実行後）にそのまま渡せる形にしなければならない

**テスト**

- **FR-027**: 検査・整形・合成・引数の検証は、作業場を使わない自動テストで確かめられなければならない
- **FR-028**: 作業場と4ツールの自動テストは、コンテナの実行環境があるときに実行し、ないときは理由を示して飛ばせなければならない。外部のネットワークには依存しない（依存のインストールのテストを除く）

### Key Entities *(include if feature involves data)*

- **作業場（Sandbox）**: ジョブ専用のコンテナ1つ。ジョブ ID、作業ディレクトリ（ホスト側のパス）、コンテナ名、資源の上限を持つ。用意 → ツールの実行 → 片付けの順に使う
- **ツール（Tool）**: 名前・説明・引数のスキーマ・実行関数。結果はモデルに返す文字列、エラーかどうか、記録用の詳細（終了コード、所要時間、打ち切りの有無など）を持つ
- **ツール呼び出し（Tool call）**: ツール名と引数。検査の入力になる
- **検査（Guard）**: ツール呼び出しを受け取り、許可するか、理由付きで拒否するかを返す
- **整形（Result transform）**: ツール呼び出しと結果を受け取り、整えた結果を返す
- **作業場の設定**: イメージ名、実行ユーザー、資源の上限、時間の上限、禁止パス、出力の上限

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 隔離の確認項目（外部への通信、作業ディレクトリ外への書き込み、`.git` への書き込み、管理者権限・特権の有無、プロセス数の上限）を自動テストで確かめ、すべて「できない」ことを 100% 確認できる
- **SC-002**: ジョブの処理が成功・失敗・例外のどれで終わっても、終了後にそのジョブの作業場が1つも残らない
- **SC-003**: 拒否されるべきツール呼び出し（作業ディレクトリ外・禁止パス・シンボリックリンク経由・危険なコマンド）の確認セットで、見逃しが 0 件。許可されるべき呼び出しの確認セットで、誤った拒否が 0 件
- **SC-004**: 作業場がすでにある状態で、1回のツール呼び出し（読み取り・書き込み・置換・短いコマンド）が1秒以内に結果を返す
- **SC-005**: 作業場の用意が10秒以内に終わる（イメージ取得済みの状態で）
- **SC-006**: 出力の上限を超えた結果は、必ず上限＋省略の注記以内の長さに収まり、秘密情報の値が平文で現れない
- **SC-007**: 作業場の環境変数に、ファクトリーに渡した APIキー・トークンが 1 件も現れない

## Assumptions

- コンテナの実行環境は Docker とし、操作は CLI から行う（`03` 5章）。gVisor（`runsc`）は任意で、本機能では扱わない
- 作業場のイメージは `node:24-slim` に git・ripgrep・pnpm を足したものとする。対象リポジトリのパッケージマネージャーのバージョンが違う場合の対応は扱わない（デモ用リポジトリは同じ pnpm にそろえる）
- clone・作業ブランチの作成・commit・push はホストで行い、本機能では扱わない（007・008）。本機能は「clone 済みの作業ディレクトリ」を受け取る
- 依存のインストールのコマンド（例: `pnpm install --frozen-lockfile`）は呼び出し側が渡す。本機能はコマンドを決めない
- 工程内テスト（lint・型チェック・テスト）の決め打ちのコマンドは 005 で決め、本機能の作業場の上で実行する
- 実装役のエージェントへの組み込み（Pi の `AgentTool`・`beforeToolCall`・`afterToolCall` への接続、逐次実行の設定）は 004 で行う。本機能は Pi に依存せず、フックの形に合わせた関数を用意する
- 拒否が続いて先に進めないときにジョブを止める判断（`terminate`）は 004 の停止条件で扱う
- 軌跡への記録は 004 で行う。本機能のツールの結果は記録に使える詳細を持つだけにする
- 作業場の実行ユーザーは、ホストのファクトリーのユーザーと同じ ID を既定とする（作業ディレクトリのファイルの所有者をそろえるため）。管理者の ID になる場合は設定で別の ID を指定させる
- 対象リポジトリは TypeScript（`03` 5章）で、作業場は Linux 上の1台の VPS で動かす
