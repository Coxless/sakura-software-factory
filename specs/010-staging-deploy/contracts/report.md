# Contract: レポートの追加分（010）

## 1. PR の本文のデプロイの欄

009 の CI の欄（`<!-- /factory:ci -->`）の後ろに置く。なければ本文の末尾に足す。`deployments` のそのジョブの行（古い順）から毎回作り直す。

```markdown
<!-- factory:deploy -->
#### ステージング
| commit | イメージ | 結果 | 内容 |
|---|---|---|---|
| `abc1234` | `sakura-staging-app:abc1234def56` | ✅ デプロイしました | https://staging.example.jp |
<!-- /factory:deploy -->
```

| 行の状態 | 結果 | 内容 |
|---|---|---|
| `running` | ⏳ デプロイ中 | |
| `succeeded` | ✅ デプロイしました | `public_url`（空なら「ステージングで動いています」） |
| `failed`（`fetch`・`build`） | ❌ ビルドに失敗しました | ステージングは前の版のままです |
| `failed`（`release`・`health`） | ↩️ 戻しました | 戻し先（`rolled_back_to`、なければ「ステージングを止めました」）、戻した版のヘルスチェック、revert PR（`#n`、なければ作らなかった理由） |
| `failed`（`interrupted`） | 🛑 中断しました | |

- 本文全体は伏せ字（`maskWith`）にかけてから書く。書けなければ `deploy_body_failed` を残す（デプロイはやり直さない）

## 2. Issue への報告（ロールバックしたとき、1回）

```markdown
### 🏭 ファクトリー: ジョブ #12 の変更をステージングから戻しました

| 項目 | 内容 |
|---|---|
| PR | #34 |
| commit | `abc1234` |
| ヘルスチェック | 3 回中 0 回成功（最後: 500） |
| 戻し先 | `sakura-staging-app:0123456789ab`（戻した版のヘルスチェック: 通過） |
| revert PR | #35（auto-merge は有効にしていません。確かめてからマージしてください） |
```

- 戻し先がない: 「なし（ステージングを止めました）」
- revert PR を作らなかった: 「作りませんでした（理由）」
- 取得・ビルドの失敗は 007 の失敗の報告（理由 `deploy_failed`。止まった工程 `deploying`）に、失敗の段階とエラーの末尾を `detail` で付ける

## 3. revert PR

- 題: `Revert abc1234（ステージングのヘルスチェックの失敗）`
- ブランチ: `factory/revert-<after の先頭 7 文字>`、ベースは既定のブランチ
- `draft: false`、auto-merge は有効にしない、ラベルは付けない

```markdown
### 🏭 ファクトリー: ステージングで動かなかった変更を戻す PR

`abc1234`（PR #34）をデプロイしたところ、ステージングのヘルスチェックが通らなかったため、ステージングを直前の版に戻しました。
この PR は `<before 7 文字>..abc1234` の変更を打ち消します。

| 項目 | 内容 |
|---|---|
| ヘルスチェック | 3 回中 0 回成功（最後: 500） |
| 戻し先 | `sakura-staging-app:0123456789ab` |

検査役の判定を通っていないため、auto-merge は有効にしていません。内容を確かめてからマージしてください。
```
