# 企画概要とコンテスト戦略

さくらのVPS × さくらのAI Engine による自律型ソフトウェアファクトリーの企画概要。
定義・方針は `01_ソフトウェアファクトリーの定義と方針.md`、構成の詳細は `03_アーキテクチャと技術スタック.md` を正とする。

## 1. 企画概要 & 背景
- 対象コンテスト: Zennfes Autumn 2026「AIでつくる、公開する、動かし続ける。さくらのAIチャレンジ祭り」
  - コンテストURL: https://zenn.dev/contests/zennfes-autumn-2026-sakura
  - 開催期間: 2026年11月2日 〜 2026年12月16日
- 狙う賞:
  - さくらのVPS 24時間稼働チャレンジ部門: 24時間稼働アイデア賞（Amazonギフトカード 1万円分）
  - さくらのAI Engine 3,000リクエストチャレンジ部門: ものづくり賞 または 徹底検証賞（Amazonギフトカード 2万円分）
- コアコンセプト:
  - さくらのVPS上で24時間自律稼働する「自律開発エージェント・ファクトリー」
  - GitHub Issue のコメント（Webhook）をトリガーに、エージェントがコード生成・テスト・静的解析を隔離環境（Docker）で実行し、PR作成 → CI通過後の自動マージ → ステージングへの自動デプロイまでを行うパイプライン（自律レベルB。本番デプロイは人間）

## 2. 過去のZennコンテスト傾向と差別化戦略

### 過去のZenn受賞傾向
1. 実用性とリアルな課題解決: 単なる Hello World やチュートリアルではなく、「開発現場で本当に使える」「自身の困りごとを解決した」ストーリーが評価される
2. アーキテクチャの厚み・技術スタックの融合: 単一API呼び出しだけでなく、インフラ（VPS）、コンテナ（Docker）、CI/CD（GitHub Actions/Webhook）、エージェント基盤を組み合わせた総合力
3. 再現性・トラブルシューティングの明文化: ハマりどころ、レイテンシ検証、トークン管理、エラーハンドリングなどの知見が読者に刺さる

### 先行記事との差別化
- 先行事例: 『無料枠3,000リクエストで「新規事業のAIエージェントチーム」 ─ さくらのAI Engine 5モデルを分担させる日次バッチ』（2026/11/07投稿）
  - ニュース要約やビジネス企画案を日次でメール送信するバッチ処理
- 本プロジェクトの優位性・独自性:
  - コード生成・実環境テストまで踏み込む: テキスト出力にとどまらず、リポジトリに対する変更・テスト・PR生成まで完結させる「実稼働ソフトウェアファクトリー」
  - 推論を国産・非学習（Zero Data Retention）で閉じる必然性: プライベートコードや社内資産を扱う以上、「さくらのAI Engine（学習・保存されない）」を選ぶ明確な理由がある（リポジトリは GitHub のままなので「国産インフラで完結」とは言わない）
  - DevSecOps的サンドボックス設計: VPSホストを破壊しないよう、エージェントの実行環境を Docker コンテナ / 軽量サンドボックス内に厳格に隔離する運用設計

## 3. システム構成の概要

```
GitHub（Issue コメント "@agent" / Actions による CI / ブランチ保護 + auto-merge）
   │ Webhook
   ▼
さくらのVPS（常時稼働）
  ├─ factory: Webhook 受付 → ジョブキュー → 工程の状態機械
  │    ├─ 計画・実装・検査を別役割（別モデル）で実行 ──▶ さくらのAI Engine
  │    ├─ コード実行は Docker サンドボックス内に隔離
  │    └─ PR作成 → CI結果のフィードバック → 自動マージ → ステージングへデプロイ
  └─ staging: デモアプリ（ヘルスチェック失敗時は直前の版に戻す）
```

詳細は `03_アーキテクチャと技術スタック.md`、安全設計は `04_ガードレールとハーネス設計.md` を参照。

## 4. 記事構成案（Zenn投稿用ドラフト骨子）
1. はじめに
   - なぜ「VPS × 24時間常時稼働エージェント」なのか？
   - AIコーディングアシスタント（ローカル作業）から「自律開発ファクトリー（バックグラウンド常時稼働）」への進化
2. なぜ「さくら」の組み合わせなのか？
   - さくらのAI Engine: Zero Data Retention（コードが学習されない安心感）、月3,000リクエストの無償枠の活用
   - さくらのVPS: 常時稼働の Webhook 受信エンドポイント兼サンドボックス実行環境・ステージング環境
3. アーキテクチャと安全設計（サンドボックス分離）
   - エージェントが勝手にコマンドを実行するリスクの排除（Dockerによる隔離、リソース制限、権限最小化）
4. 実装のポイント
   - Webhook ハンドラーとキュー管理
   - さくらのAI Engine のエンドポイント設定とプロンプトチューニング
   - エージェントによる自律テスト実行 & リトライ機構（テストが落ちたら、エラー出力を渡して自動修正）
   - CI連携・自動マージ・ステージングデプロイとロールバック
5. 月3,000リクエスト枠の消費検証・コスト考察
   - 1 Issue あたりのリクエスト数・トークン消費の実測値
   - 無料枠内で1ヶ月に何本の PR / Issue をさばけるかのシミュレーション
6. まとめと展望
   - AI時代のレビューボトルネックへの示唆と、今後のセルフホストエージェントの可能性
