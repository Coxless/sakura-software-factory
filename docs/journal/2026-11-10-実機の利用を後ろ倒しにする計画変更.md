# 実機（VPS・AI Engine）の利用を後ろ倒しにする計画変更

## 何が分かったか

- さくらのVPS の無料期間は2週間。使い始めた日から数える
- さくらのAI Engine の無償枠は月3,000リクエスト（無償枠で使えるのは Chat Completions だけ）

元の実装計画は、11/11 までに実機でツール呼び出しを確かめ（M0）、11/19〜11/24 に VPS で24時間稼働を始める前提だった。この順序のまま VPS を 11月中に使い始めると、無料期間が締切（12/16）より前に終わる。

## 決めたこと

- **VPS は 12/03 に使い始める**（12/03〜12/16 の14日間を無料期間に合わせる）。006 の配備物（Caddyfile・systemd・手順書）は M2 で用意してローカルで流しておき、12/03 は手順書を上から流すだけにする
- **実機の LLM は「AI解禁」まで呼ばない。** AI解禁は、005（ローカルで計画から判定まで）が偽の LLM で通ったあと（予定 11/25）。11月の枠は月末で消えるので、解禁後は 11月の枠を実機の調整に使う。12月の枠は、24時間稼働のデモと回帰評価・検査役の比較に使う
- 002 のスモークテスト（T019・T020）は AI解禁の日の最初の作業にする。002 はそれ以外のタスクでマージしてよい

## 比べた選択肢

- 元の計画のまま 11/11 にスモークテストだけ回す（10リクエスト以下）: Pi か TanStack AI かの判断が早く決まり、004 を作り直す危険が減る。ただし「準備が整うまで実機を使わない」方針に合わないので採らなかった
- 代わりに、切り替えたときに書き直す範囲を `src/llm/provider.ts` と `src/llm/stream.ts` の内側、004 の Agent の組み立てに閉じ込めて進める（ゲート・記録・偽の LLM・ツール・ガードは使い回せる）

## まだ分かっていないこと

- 審査期間中（12/16 以降）も VPS を動かしておく必要があるか。必要なら有料で延長する
- AI解禁が遅れて 12月にずれ込んだ場合、11月の枠を使えずに 12月の 3,000 だけで調整・運用・評価を賄うことになる
