## なぜこうなるか（今の作り）

- **PR のコメントは受け付けない**: `src/github/events.ts` の `toAgentRequest` は、`issue_comment` のうち `issue.pull_request` があるものを `ignored`（`pull_request`）にする。PR の会話タブのコメントも GitHub では `issue_comment` で届くが、ここで捨てている。応答もしないので、使う側には「無視された」ことが分からない
- **Issue で頼み直すと必ず新しいジョブ・新しいブランチ**: `src/pipeline/worker.ts` でブランチは `agent/issue-<Issue>-job-<ジョブ>`。新しいジョブは最新の既定のブランチから作り直すので、衝突は消えるが、前の PR は残る。前のジョブ・PR を引き継ぐ手段がない
- **衝突を知る手段がない**: job 22 は `ci_waiting` のまま待っていた。衝突した PR では CI が走らないことがあり、そのままなら `ci_wait_timeout_minutes` まで待つことになる。今回は人が閉じたので `pr_closed` で終わった。ファクトリーは衝突（`mergeable: false`）を見ていない
- **並行して進む Issue で起きやすい**: 08:00〜08:20 の間に #58〜#67 と PR が続けてマージされていた。同じファイル（ここでは `src/server.js`）を触る Issue を続けて流すと、計画〜PR の数分の間に既定のブランチが進んで衝突する

## 気づいたこと

- `@agent` は GitHub に実在するアカウント `agent` へのメンションになる。`gh api users/agent` では `type: Organization`（2015-12-02 作成）。PR #66 のタイムラインには `mentioned`（`agent`）が残る。Organization へのメンションで誰に通知が届くかは確かめていない

## まだ分かっていないこと・決めていないこと

- PR のコメントでの依頼を受けるか。受けるなら、その PR のジョブ・ブランチを引き継いで既定のブランチを取り込み（rebase か merge）、衝突を直させるのか、閉じて作り直すのか
- 受けないなら、PR で `@agent` と書かれたときに「Issue で頼んでください」と返すだけでもよいか
- Issue で頼み直したとき、同じ Issue の開いている前の PR を閉じる（またはそちらを直す）か
- `ci_waiting` の間に衝突を見つけたら、待たずに止めて報告するか

## 追記: `@agent` を `/agent` に変えた

- `agent` は `AGENT, Inc.`（`https://joinagent.com`）の Organization。公開メンバーは 0 人
- 公開リポジトリ `Coxless/factory-sandbox` の Issue コメントで、最初の行が `@agent` のものは 23 件あった（`gh api repos/Coxless/factory-sandbox/issues/comments` で数えた）。本体リポジトリでも、PR の本文 19 件が `gh search prs "@agent"` に当たる（本当にメンションになっているかは見ていない）
- GitHub で通知が届くのは個人と Team（`@org/team`）へのメンションで、Organization そのもの（`@org`）へのメンションでは誰にも通知されないはず。ただし確かめてはいない
- 比べた案: `/agent`（スラッシュコマンド）、`@<App の名前>`、`` `@agent` ``（コードで囲む）。`/agent` にした。GitHub は `/` で始まる言葉をメンションにしない。App の名前でのメンションはボットアカウント（`…[bot]`）に届く仕組みではなく、同じ名前のアカウントを他の人が取れば同じことが起きる。コードで囲むのは書くたびに手間がかかり、今の判定ではコードの中を依頼にしないので、扱いを逆にする必要がある
- 変えたのは判定（`src/github/events.ts` の `AGENT_LINE`）と、journal を除くすべての文書・テスト・fixture（55 ファイル、109 か所）。`@agent 直して` は依頼にならないことをテストに足した
- 先方への連絡はしない。通知が届いていない見込みが高く、連絡するとかえって相手の手間になる。新しいメンションを止めることを対応とした
