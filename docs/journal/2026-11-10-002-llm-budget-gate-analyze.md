# 002 llm-budget-gate の analyze と直したこと

## やろうとしたこと

実装に入る前に `/speckit-analyze` で spec・plan・tasks を突き合わせた。CRITICAL は0件、要求のカバー率は100%（FR 26件・SC 7件、タスク36件）。HIGH 1件、MEDIUM 4件、LOW 5件が出た。

## 見つかったことと決めたこと

- **タイムアウトのテストが10秒に収まらない（HIGH）**: 試行の時間の上限を `AbortSignal.timeout(request_timeout_seconds)` で作る計画だったが、設定の最小値が10秒なので、本物のタイマーではタイムアウトのテストに10秒以上かかり、SC-006（ゲートのテストが10秒以内）と両立しない。`now` を注入しても `AbortSignal.timeout` は発火しない。→ `GateDeps.timeoutSignal` を注入できるようにし、テストでは手動で中止する
- **素の HTTP が非ストリーミングだった**: Pi 経由はストリーミング、`--raw` は `stream: false` で、「同じ要求」になっていなかった。この差があると、ストリーミング特有の問題（`delta.tool_calls` の分割、usage のチャンク）を「Pi の問題」と取り違え、TanStack AI への切り替えを誤って判断しうる。→ `--raw` も既定でストリーミングにし、`--raw --no-stream` を追加の切り分けに残した
- **SC-001 の「2分以内」**: 既定のタイムアウト（5分）と再試行（3回）があるので、最悪の場合は 3要求 × 3回 × 5分 となり2分に収まらない。→ スモークテスト用の短いタイムアウトは足さず、SC-001 を「正常時（再試行もタイムアウトも起きないとき）」に限定した
- **憲法の「偽の `streamFn`」**: 計画では、状態コードやヘッダー、接続の切断を再現するために、偽の `fetch` をゲートの内側に差し込む（research R13）。憲法の文言とずれていた。→ 憲法を PATCH（1.0.0 → 1.0.1）で「偽物に差し替える（予算ゲートの内側に差し込む）」に直し、`docs/design/03` の2か所も同時に直した
- そのほか、失敗の種類に「タイムアウト」を足した（FR-016）。上限を超える `retry-after` を `permanent` にする理由を research R6 に書いた。`smoke-llm.ts` に終了コードのテストを足した。既存の `error` 行は `error_kind = 'permanent'` で移すことにした。T017 と T018 の順序を入れ替えた。journal のファイル名の `XX` をやめた
