# 2026-11-14 012 回帰評価（evals）

## やろうとしたこと

ハーネスを変えたときに「どの変更が、どれだけ効いたか」を数値で見るための回帰評価を作る。`evals/` のサンプル Issue を 005 の工程（計画から判定まで）で回し、成功率・消費リクエスト数・処理時間を前回と比べる。12月の枠では検査役（Qwen3.6 と gemma-4）の比較にも使う。AI解禁前なので、偽の LLM でテストが通る状態まで作った。

## 選択肢を比べて決めたこと

### 成功を何で決めるか

- 候補: (a) 検査役の合格だけ、(b) 人が採点、(c) LLM に採点させる、(d) 工程の合格＋隠しチェック
- (d) にした。(a) は検査役の甘さが成功率に混ざり、検査役の比較の「正解」にも使えない。(b) は再現性がなく記事の数値にならない。(c) は枠を食い、検査役の比較の正解として循環する
- 工程が不合格でも隠しチェックは回して記録する。これで「検査役が誤って不合格にした」件数も数えられる

### 隠しチェックをどう隠すか

- 隠しのファイル（`hidden/`）は工程が終わるまで作業ディレクトリに置かない。作業場は `--network none` で作業ディレクトリしか見えないので、計画役・実装役・検査役のどの入力にも出ない（偽の LLM の要求の本文に目印の文字列が出ないことをテストで確かめた）
- 工程のあとで同名のファイルを**上書き**して置く。実装役が `.eval/x.test.ts` を自分で作っても、採点のときは隠しの版になる
- lint 解消のケースでは、実装役が `scripts/lint.ts` の規則を弱めて通す抜け道があるので、元の `scripts/lint.ts` を `hidden/` に置いて採点前に戻すようにした

### 対象のプロジェクト

- 外部の公開リポジトリを clone する案はネットワーク依存と版の固定が要るのでやめた
- 依存のない小さな TypeScript のプロジェクト（`evals/projects/inventory`）を1つ置き、ケースごとの初期状態は `setup/` の重ね合わせで作る。テストは `node --test`、lint は自前の `scripts/lint.ts`。作業場のイメージ（node:24-slim）だけで動き、インストールが要らない
- 作業の種類ごとに1件、計5件（test・bugfix・lint 解消〔chore〕・docs・refactor）。1件 20〜50 リクエストの見込みで、全件1回が 100〜250 リクエスト

### 検査役の比較のしかた

- 候補: (a) 検査役のモデルを変えて評価全体を2回回す、(b) 主の検査役の最後の判定と同じ入力を比較用の検査役にも1回渡す
- (b) にした。(a) は実装役のばらつきが混ざり、消費も倍になる。(b) は追加の消費が1ケース1〜2リクエストで済む
- 記録は `llm_calls.phase = 'judge_alt'`、役割は `verifier` のまま（`llm_calls.role` の CHECK 制約が planner / implementer / verifier だけなので）。`agent_runs` の一意制約（job, phase, attempt）にもぶつからない
- 005 の `runPipeline` の結果に `lastJudge`（最後に検査役へ渡した diff とテスト結果）を足した。最後の回がテスト失敗などで判定されなかったときは、検査役が見た diff と採点した diff がずれるので、一致率の分母から外す

### 評価全体の上限と原則 V

- 評価全体のリクエスト上限は、ケースごとに1ジョブの上限を「評価の残り」まで下げて守る（予算ゲートの変更が要らない）
- `/speckit-analyze` で、評価は受付（webhook）を通らずにジョブを作るので「月の残りが1ジョブの上限を下回ったら新しいジョブを受け付けない」（原則 V）が効いていないと指摘された。各ケースの前に `canAcceptNewJob` を下げた上限で呼ぶようにした

## 想定と違った挙動

### `node --test` の中から `node --test` を呼ぶと、子の失敗が終了コードに出ない

`test-format-price` の隠しチェックは、`formatPrice` を壊した版に差し替えた複製で、エージェントのテストが落ちることを確かめる（ミューテーションテストの簡易版）。最初の版は模範解答でも全部の壊した版で「テストが通りました」と出て失敗した。

```
✖ 壊した版（カンマ区切りなし）でエージェントのテストが落ちる (37.645167ms)
  AssertionError [ERR_ASSERTION]: 壊した版（カンマ区切りなし）でもテストが通りました
    actual: 0,
    expected: 0,
    operator: 'notStrictEqual',
```

子プロセス（`spawnSync(process.execPath, ["--test", "test/price.test.ts"])`）が 37ms で終了コード 0 を返していた。親のテストランナーが設定する環境変数 `NODE_TEST_CONTEXT` を子が引き継ぐと、子は結果を親に報告する形で動き、失敗しても終了コードが 0 になる。子に渡す環境変数から `NODE_TEST_CONTEXT` を外したら、4種類の壊した版をすべて見つけられるようになった。

### Workshop の中で `pnpm run secrets:scan` が 0 コミットになる

worktree の `.git` はホストの絶対パス（`/home/.../.git/worktrees/012-evals`）を指していて、Workshop の `/project` からは見えない。gitleaks は `fatal: not a git repository` を出して 0 コミットのスキャンで「no leaks found」になる。worktree で作業したときは `gitleaks dir --config .gitleaks.toml src evals specs docs …` でファイルの中身をスキャンした（漏れなし）。
