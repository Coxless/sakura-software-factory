# 006 vps-ops のレビューで見つけた2点（sshd の設定の読み順、停止の待ち時間）

PR #6（006 vps-ops）を要件と突き合わせたときに見つけ、直した2点。

## 1. `sshd_config.d/50-sakura-factory.conf` ではパスワードでのログインが止まらないことがある

### 何が問題だったか

`setup.sh` は `/etc/ssh/sshd_config.d/50-sakura-factory.conf` に `PasswordAuthentication no` を書いていた。sshd は**同じ設定名なら先に読んだ値を使い**、`sshd_config.d/*.conf` は名前順に読む。Ubuntu の cloud-init のイメージには `50-cloud-init.conf`（`PasswordAuthentication yes` のことがある）がある。`50-cloud-init` は `50-sakura-factory` より名前順で先なので、こちらの `no` は使われない。

予行演習は `FACTORY_SKIP_SSH=1` で SSH の手順を飛ばすため、この点は一度も確かめられていなかった。

### 再現（Workshop の Docker、`ubuntu:24.04`、OpenSSH_9.6p1 Ubuntu-3ubuntu13.20）

```bash
apt-get install -y openssh-server && mkdir -p /run/sshd
printf "PasswordAuthentication yes\n" >/etc/ssh/sshd_config.d/50-cloud-init.conf
printf "PasswordAuthentication no\nKbdInteractiveAuthentication no\nPermitRootLogin prohibit-password\n" \
  >/etc/ssh/sshd_config.d/50-sakura-factory.conf
sshd -T | grep -E "^(passwordauthentication|kbdinteractiveauthentication|permitrootlogin) "
```

```
--- 旧名 50-sakura-factory.conf:
permitrootlogin without-password
passwordauthentication yes        ← cloud-init の値が勝つ
kbdinteractiveauthentication no
--- 新名 01-sakura-factory.conf:
permitrootlogin without-password
passwordauthentication no
kbdinteractiveauthentication no
```

- `sshd -t`（文法の検査）はどちらでも通る。文法の検査だけでは、この問題に気づけない
- `PermitRootLogin prohibit-password` は、`sshd -T` では旧名の `without-password` で表示される

### 結論

- ファイル名を `01-sakura-factory.conf` にする。旧名のファイルが残っていれば消す
- `sshd -t` のあとに `sshd -T` で実際に効く値を確かめ、`passwordauthentication no`・`kbdinteractiveauthentication no`・`permitrootlogin (prohibit-password|without-password)` でなければ止める
- 手順書の「確かめ方」に `sshd -T` の行を足す

### まだ分かっていないこと

- さくらのVPS の Ubuntu 24.04 のイメージに `50-cloud-init.conf` があるか、その中身。VPS解禁の日（12-03）に `ls /etc/ssh/sshd_config.d/` で確かめる

## 2. `TimeoutStopSec=20` と `shutdown_timeout_seconds` の上限 60 が食い違っていた

- `factory.service` には「`shutdown_timeout_seconds` の上限より長くする」とコメントがあった。しかし値は 20 で、設定では 1〜60 を指定できる。21〜60 を指定すると、ファクトリーが自分で終わる前に systemd が SIGKILL を送り、SQLite を閉じられない
- 設定の上限を下げる案もあったが、`TimeoutStopSec=70` にしてユニット側で合わせた。既定の 10 秒で終わるので、SC-004（10 秒以内に終わる）は既定の設定のまま満たす
